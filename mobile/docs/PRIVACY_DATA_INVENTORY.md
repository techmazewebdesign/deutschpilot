# Native data inventory — 1.1.0 (5), 20 October 2026

Engineering inventory for privacy and App Store review. This is not an approved legal notice, completed privacy label or certification of German-law compliance. Optional signup and optional school features still count as collection. An empty app-level `NSPrivacyCollectedDataTypes` list does not justify “Data Not Collected”. School deployment requires documented controller/processor roles, contracts, legal bases, retention and supplier review.

| Data / feature | Implementation and destination | Release review required |
| --- | --- | --- |
| Email/password credentials, Firebase UID, verification/reset state | Firebase Authentication; passwords handled by its SDK. Server verifies identity before school/private learning access | Identity linkage, processor terms, account security, retention and deletion |
| Display name/email and school membership/role | Account profile and authenticated school service; school-specific access checked server-side | Role administration, least privilege, school provisioning and notice |
| Google/Apple authentication helpers | Google UI remains hidden on iOS; existing Apple helper is not presented as a proven provider | Final SDK inventory and actual provider/device testing; no unverified support claim |
| Guest lesson completion, XP, level, streak/daily goal and vocabulary review | AsyncStorage. Guest data is separate from per-UID account storage; switching accounts clears visible account state | Shared-device use, backups, local reset and explicit migration choices |
| Account-linked lesson completion | Authenticated school progress service; monotonic completion/best score; only known native lessons affect native XP. Paginated sync reports partial status at its safety bound | Purposes/retention, web/mobile identity mapping, network-failure and account-switch tests |
| Classes, student/staff roster and attendance | Private authenticated school API, role/class scoped; RAM-only native snapshots, no school snapshot disk cache | Authorized staff access, attendance correction, retention, notices and school administration controls |
| Absence reports and optional supporting documents | Private service; optional sensitive information requires configured legal basis/operator settings. Teachers receive minimal date/status summaries, not medical reasons or files | Specific health-data legal basis and safeguards, necessity/minimization, retention, authorized office access and school policy. Do not solicit diagnoses |
| Private uploaded PDF/JPEG/PNG documents and requests | Authenticated upload/download, server quarantine and trusted scanning required; no public URLs. Native temporary picked/downloaded files cleaned after use | Scanner/storage configuration, processing locations, access audit, deletion/holds, file limits and sensitive-category handling. Upload is disabled when required scanning is unavailable |
| Letters, read/acknowledgment records and signed returned copies | Private service. Optional native PDF printing/sharing uses temporary files; explicit export notice | Acknowledgment is not a qualified electronic signature. Exported copies leave app control; recipient and retention procedures required |
| Per-class chat text, author/time, read marks and moderation | Authenticated class service; shared with assigned class members/teachers. Foreground polling/manual refresh; no health documents or private upload channel in class chat | School communication rules, member removal, moderation, retention, audit and students' rights |
| Inbox notifications | Private account inbox and read state, authenticated API | Content minimization, purposes and retention |
| Optional Expo push token / delivery metadata | Explicit device permission and backend registration only when provider configuration is available. Generic notification body, no diagnosis/document/message content. Logout can queue UID-bound unregister cleanup while still allowing offline signout | Expo/APNs processors and credentials, permission/revocation behavior, real-device delivery/receipt tests. Permission or registration alone is not proof of delivered push |
| Theme | Local AsyncStorage preference, separate from learning reset | Preference retention |
| Account deletion | Authenticated existing `/api/account/delete`; server owns complete account/school cleanup or documented lawful retention | Disposable-account full deletion test, processor retention, legal holds and user explanation; local reset is a separate operation |
| German text to speech / haptics | OS system TTS via expo-speech and device feedback; no microphone recording or speech scoring | Installed voice/offline behavior; final permission manifest review |
| Policy/support links and learning material | Browser/mail links; bundled project learning text | Operator identity, accurate live notices, rights and curriculum review |

Native authorization failures clear private school snapshots immediately. Network failures can leave explicitly stale data in RAM until refresh/signout; private school snapshots are not persisted offline. Temporary file cleanup cannot erase a copy the user deliberately exports to another application. OS backups, screenshots and external recipients require separate policy and device review.

The candidate adds school cloud processing and uploads, so the earlier learning-only inventory is superseded. No production migration, authentication-provider change, real-user test, payment activation or public release is established by this implementation. Final privacy notices, App Store labels, SDK/native manifests, infrastructure logs, support procedures and processor contracts must be reviewed against the deployed configuration before release.
